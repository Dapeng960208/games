# 开发规范

更新：2026-10-03。用户最新指令优先。Windows 中文 Markdown 使用 UTF-8，读取指定 `Get-Content -Encoding UTF8`。存在 `.codegraph/` 时先 CodeGraph；不存在时不自行索引，普通搜索先 `rg`。

## 目录与命名

完整目录树、文件放置责任与迁移检查见 [目录结构规范](engineering/repository_structure.md)。

角色资源和文档按 `characters/{warrior,gunner,mage}`；系统按 `system/<feature>`；关卡按 `levels/b01...b12`，普通怪 `enemies` 与首领 `bosses` 分开，每种再按稳定 ID 建目录。已实现关卡的资源位于 assets；未实现关卡只在 docs 保留明确标注的设计。

物理目录、文件名统一小写 `snake_case`，资源按语义命名，不在文件名重复职业/关卡或堆叠版本。确需保留有效备选，使用清楚的用途名；来源记录保留原始版本和哈希。CH/BO/M/EQ/L 等稳定内容 ID 不因搬迁改变，不能重排存档身份。

`assets/manifest.json` 统一登记逻辑 ID 与物理路径，脚本经 `AssetCatalog.resolve` 加载；目录枚举使用逻辑索引。角色动作 JSON、纹理、region、脚点、来源与许可共同维护。新增资源先登记，工具拒绝写未登记或越出 assets 的目标。

## 代码职责

| 目录 | 责任 |
|---|---|
| scripts/app | 生命周期、用例服务、提交和信号 |
| scripts/domain | 战斗、装备、远征、成长与世界规则 |
| scripts/gameplay | 游戏节点、物理、行为与房间生命周期 |
| scripts/presentation | 页面、HUD、绘制和反馈 |
| scripts/infrastructure | 资源、内容配置、保存、音频、输入与本地化 |
| scripts/levels | 单关专属机制，共有规则放 domain |

表现不计算或发放实际奖励；领域规则不引用具体页面。主控制器保留状态与生命周期，拆出的服务按责任组织；新增功能避免回填到大控制器，避免隐式新增跨服务共享字段。保存检查点只保存值数据，不能保存节点。

场景按 app/gameplay/presentation，数据按 characters/equipment/monsters/world/levels/rules/localization，着色器按 world/levels，检查按系统/关卡归类。工具的项目根从 `project.godot` 定位，不能依赖搬迁后失效的固定父层数。入口 `tools/run.ps1`、`setup.ps1`、`test.ps1` 保持可直接运行。

## 游戏与视觉约束

明亮手绘卡通奇幻、高机位斜俯视、近等距 2.5D、暖阳和清新配色；统一人物尺度、脚点、描边、材质和镜头。装备采用成人穿戴比例与明确结构；种族通过轮廓、生态、建筑和机制区分。UI 使用羊皮纸、黄铜、深紫文字、圆技能徽章与当前用途按钮。

地形、功能点、路线人工固定。禁止整房覆盖 `data/world/fixed_rooms.json`：设计 JSON 仅按批准字段合并，保留种族、首领反制、固定奖励、遭遇、任务和状态。地景与可走多边形共用变换，所有点可达；身体脚点排序、遮挡淡化、碰撞使用地面足迹。

角色正式方向为八方向 E／SE／S／SW／W／NW／N／NE，移动与瞄准保持连续；动画转向保持动作相位，按统一站立参考与脚点显示，不以 30°／60° 候选改名代替 45°。

绘制使用本次提交方向，视觉不驱动伤害。自动普攻遵守距离、视线和资源；动作队列有界，暂停/弹窗/背包/闪避/死亡/切房清空。新增敌群使用有限波次，保留并发、弹体和召唤边界。

## 保存与清理

当前新格式存档继续使用；已完整验证的旧 schema/旧数值格式保留原始备份后从新进度开始。未知或损坏文件阻止写入并保留字节，不能靠缺字段将坏档误判为可重置旧档。购买、打造、锻造、奖励和撤离均一次提交，重复或失败不重复扣款、发奖或重抽。当前实例里的有效历史付款/资格元数据仍需验证和保留。

实际玩家档 `%APPDATA%/AbyssSalvagerM1/profile.json` 不纳入仓库清理。测试必须隔离。构建、下载、隔离档、日志、截图副本、试听、Python/Godot 缓存不入库。来源、版权、许可和仍被当前动态加载使用的资源不能作为垃圾删除。

清理和移动先确认目标不被活跃进程使用，检查绝对目标在授权工作区内。已失效历史不建立新的 archive/drafts 文档树；当前设计、候选协议及必要回归输入保留明确状态。

## 检查与提交

按责任提交，便于 diff；默认 main，用户另行要求分支时使用指定分支。不要覆盖其他人的更改或强推。多 agent 仅获授权才使用。

只运行直接相关检查：资源搬迁做导入/解析与动态资源检查，保存修改做事务/恢复检查；退出码零仍核对 SCRIPT ERROR/ERROR。套件从 `tools/testing/suites.json` 注册，目录/资源/文档用 `tools/maintenance/audit_repository.py` 核对，不默认跑全部套件。

文档状态不得混淆：已接入、候选／待验证、未实现。真实截图、设计图与测试结果分开描述；无界面或软件渲染结果不能冒充目标硬件与自然玩法验收。
