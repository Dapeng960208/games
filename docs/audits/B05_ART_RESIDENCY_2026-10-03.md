# B05 首次资源驻留修复（2026-10-03）

## 已确认问题与改动

`b05_enemy_art.gd` 原来首次查询任意一个 B05 普通怪，就加载两个正式 manifest 中的全部 18 种怪物、54 张姿态纹理。原始 manifest 3 种、再生成 manifest 15 种，身份集合不重叠，并非重复载入两代同种怪物。按正式 PNG 原尺寸、RGBA8 加完整 mip 链估算，这批纹理约 432 MiB；该数字不是实测进程 RSS。

现按请求身份缓存加载，仅读取该怪物的三个姿态。保留 manifest 优先顺序、缺失回退、来源、脚点、身体比例、姿态别名和全部正式图片，不改战斗、数值或存档。单种约 24 MiB 的纹理预算代替首次无条件加载 432 MiB；依然保留已遇到怪物的缓存，因此不是全局内存上限或全部内存问题的最终修复。

## 定向检查

`tests/test_b05_art_residency.gd` 通过：未知身份不加载，原始 B05-M01 与再生成 B05-M03 可加载，首次 1 bank/3 texture，重复查询不增加，第二种共 2 bank/6 texture，来源及姿态别名不变。实际 Godot 4.6.3 headless，退出码 0，0 failures，无 SCRIPT ERROR/ERROR；子进程峰值 RSS 185544 KiB（约 181 MiB）。使用测试管理器和独立测试档，无图形、无战斗或完整资源扫描。

本次未做长时间图形试玩，不据短检查宣称卡死全部解决。宿主整体内存还包含工具运行时；累计 OOM 计数不能单独证明某次卡死的受害进程。全局 TextureSampler 长期缓存和 B01–B04 敌人注册预加载仍需另行定向诊断。

## 前四章后续定向修复

`enemy_art.gd` 同样从“首次查询加载全前四章”改为按请求怪物身份加载本体、对应变体和批准的 HD 替换。图鉴逐项请求时仍能得到全部素材；专门需要遍历内部注册表的既有 HD 审查明确调用 `_load_all_for_audit()`。不改原始变体顺序、ID、脚点、透明画布或替换批准列表。

`tests/test_enemy_art_residency.gd` 实测 30 项通过：空/未知身份零纹理；M12 查询只登记 M12，本体重复查询不增加纹理；变体索引、确定性选择、4 个批准 HD 替换（其中 3 个 1280² 透明画布）、技能徽章保留；M37 扩充种与 BO01 首领各自加载，先前 M12 变体保持。最终仅 3 个请求本体、6 张普通采样纹理，另有 3 张特殊透明画布；峰值 RSS 212748 KiB（约 208 MiB），退出码 0，无 SCRIPT ERROR/ERROR。首次检查因测试局部变量缺少 Array 类型注解而解析失败，修正后完成上述有效检查。

另作元数据检查：9 个变体 manifest 共 599 条记录、599 个独立 texture/region，无跨身份重复；全部技能图标身份都存在于同文件 entries，按身份过滤不遗漏现有图标。本轮未执行全量高清图形审查；已加载资源仍由原静态缓存持有，不把按需加载称作全局有界缓存或泄漏根因已证实。
