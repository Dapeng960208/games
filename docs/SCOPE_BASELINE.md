# 新任务提示词：《深渊拾荒者》v0.1 原型、UI 与开发规划

## 1. 角色与执行方式

请作为兼顾游戏制作、系统设计、Godot 开发、游戏 UI/UX 与测试的开发助手，推进一个个人开发者能够维护的 2D 游戏项目。先检查现有仓库和运行环境，再设计和实现。不要只交付策划概念、静态界面或待办清单。

本提示词是当前范围基线。遇到非阻塞性缺失，采用范围最小、容易撤销的假设并记录，不要反复要求确认已明确的内容。涉及付费、账号注册、公开发布、删除既有资产或改变现有技术栈时，先取得授权。

本项目是待验证的产品假设，不是已经证明能够畅销的方案。不要引用未经核实的销量、市场规模或转化率作为依据。

## 2. Goal 与本次任务终点

### 项目总 Goal

开发《深渊拾荒者 / Abyss Salvager》的 v0.1 单人可玩纵向切片，让玩家完成：

营地准备 → 进入矿井 → 探索战斗 → 升级并组合遗物 → 选择撤离或深入 → 撤离、死亡或击败 Boss → 结算与永久解锁 → 再次出发。

一轮完整远征的设计目标为 15—25 分钟，这是待试玩验证的目标，不是已实现的体验。初版重点验证战斗反馈、遗物组合和撤离决策，不以内容量、联网或华丽演出为目标。

### 本次任务硬性 Goal

完成 M0 与 M1：建立可维护的工程与设计基线，交付一个能操作、能战斗、能拾取、能撤离、能死亡、能结算并保存结果的最小闭环，以及真正接入游戏状态的基础 UI。

M2—M4 是后续路线，不得全部塞进第一个工作单元。M1 必须有可运行实现，不能只有文档、静态截图或可点击但没有游戏逻辑的界面。

## 3. 产品定位与主题

暂定中文名：深渊拾荒者。
暂定英文名：Abyss Salvager。
名称仅作内部代号，尚未完成同名与商标可用性核查。

平台：PC，面向未来 Steam 全球发行；初版先验证 Windows。
类型：俯视角 2D 动作探索、局内升级、遗物构筑、轻量撤离风险决策。
模式：离线单人。首版不做联机，也不承诺之后必然支持联机。
语言：简体中文与英文；面向玩家的文本通过本地化键管理。
目标玩家假设：喜欢实时战斗、探索秘密和组合玩法，并希望独自完成一次短途冒险的玩家。

世界观：地表的旧工业小镇靠深渊中的遗物维生。玩家携带一盏能够驱动古代武器的提灯，深入被发光菌群和古代机械侵占的矿井，回收废金与失落记录。深渊会改变路径，但拾荒者最重要的选择始终是：带着发现回家，还是再深入一段。

一句话表达：带着会改变武器机制的遗物深入矿井，并在每个安全点决定收工回家，还是继续冒险。

主题表现采用“旧矿业设施 × 神秘提灯 × 冷色生物荧光”。不要新增饥饿、温度、提灯燃料或生存制造系统。

明确不做：多人、PvP、MMO、开放世界、自由挖掘、复杂制作、随机词条装备、交易市场、赛季、日常任务、抽卡、账号登录、在线服务、复杂技能树、多职业、大型城镇经营、完整配音、Steam 成就或云存档集成。

首版构筑只保留“基础技能 + 遗物”，不再叠加独立的装备词条系统。跨职业构筑只记入未来候选，不在单角色原型中假装已经实现。

## 5. 核心流程与损失规则

完整流程：主菜单 → 营地与准备 → 初始遗物选择 → 第 1 深度段 → 安全点决策 → 第 2 深度段 → 安全点决策 → 第 3 深度段与 Boss → 结算 → 营地。

前两个安全点允许撤离；选择深入后进入下一段，不能回头使用前一个安全点。Boss 胜利后出现结束远征的出口。没有全程追赶玩家的倒计时，也没有随时随地的撤离按钮。

| 内容 | 成功撤离／完成远征 | 死亡 |
|---|---|---|
| 起始武器与角色 | 保留，不属于可丢失战利品 | 保留 |
| 本局废金 | 100% 转入营地仓库 | 保留 20%，向下取整 |
| 本局遗物与局内等级 | 结算后清空 | 清空 |
| 本局首次发现的图鉴／档案 | 永久记录 | 同样永久记录 |
| 已在营地获得的解锁 | 保留 | 保留 |

以上比例是初始设计参数，必须集中配置。HUD 和撤离界面显示当前携带废金与当前死亡可保留数量，不用含糊的“大部分丢失”代替规则。

结算只执行一次。奖励到账、发现记录合并、远征结束标记与活动远征清除应作为同一个可恢复的存档事务处理，防止重复领取。

M1 尚未实现远征中途恢复：退出远征须明确提示将按放弃／死亡规则结算。不要提供无效的“保存并继续”按钮。

## 6. 战斗、升级与遗物

### 基础动作

角色初始生命暂定 100。普攻“火花弹”为可瞄准的远程投射物，按住攻击连续施放；主动技能“脉冲震荡”为短距离范围攻击，提供清场或打断用途；冲刺负责躲避，其冷却和无敌时间必须有明确参数。

不添加法力、体力、终极技能等额外资源。伤害、移速、射速、冷却、攻击预警和击退均数据化，当前数值标为测试值。

攻击需要清楚的发射、命中、受伤与死亡反馈。敌人攻击有可读预警；角色受伤后给予短暂保护，避免同帧多次伤害造成难以理解的瞬间死亡。屏幕震动和闪烁可降低或关闭。

### 局内升级

M2 开始加入局内等级 1—4。击杀获得经验；每次升级暂停战斗，恢复 8 点生命且不超过上限，并弹出遗物三选一。升级不自动叠加攻击百分比。

入井时额外提供一次初始遗物选择。正常完成主路线应能在 Boss 前升到 4 级，因此不依赖秘密房也能获得至少 4 次选择机会。具体经验需求通过测试调整。

### 遗物规则

最多装备 4 件；不允许同名叠加，不做背包格子、随机词条或多层稀有度。满槽时选择新遗物需要替换一件，旧遗物本局丢弃；先预览替换影响，也可取消。

候选由已保存的随机状态产生，关闭界面和重载不得刷新候选。每次候选至少含 1 件能立即生效的遗物；前置条件必须说明。可以跳过整次选择，获得一次性 10 废金补偿，不允许重复领取。

初始三选一固定为分裂镜片、余烬灯芯、弧电线圈，让玩家在第一分钟感受到选择差异。

| 遗物 | 初始效果定义 |
|---|---|
| 分裂镜片 | 主弹首次命中后产生 2 枚侧向子弹，每枚造成基础弹伤的 40%；子弹不能继续分裂 |
| 余烬灯芯 | 武器投射物命中附加燃烧，每秒 3 点伤害，持续 3 秒；重复命中刷新持续时间而不叠层 |
| 灰烬腔室 | 带有玩家燃烧状态的敌人死亡时产生小范围爆炸，伤害为基础弹伤的 50%；爆炸不能再次附加燃烧或触发死亡爆炸 |
| 燃尽阀门 | 脉冲命中燃烧敌人时结算剩余燃烧伤害并移除燃烧 |
| 弧电线圈 | 每第 3 次普攻发出的主弹，其首次命中额外触发电弧；最多伤害 2 个其他目标，每个目标受到基础弹伤的 35% |
| 感应触点 | 一次脉冲命中敌人后触发一次同规格电弧；同次施法不能因命中多个敌人重复触发 |
| 远距继电器 | 电弧可额外连接 1 个目标；没有电弧来源时显示尚未激活及前置条件 |
| 冲刺电容 | 冲刺后 3 秒内下一发主弹命中触发电弧；同一主弹最多触发一次电弧，不与线圈重复触发 |
| 穿透铆钉 | 主弹额外穿透 1 名敌人；同一投射物不能重复命中同一目标 |
| 急救封蜡 | 击杀精英敌人恢复 10 点生命，不超过上限 |
| 护灯铜环 | 每个安全点首次抵达时恢复 10 点生命，反复进出不得重复触发 |
| 探路透镜 | 提示当前深度段相邻房间类型；有秘密入口时提供方向线索，不直接发放奖励 |

M1 只实现分裂镜片、余烬灯芯、弧电线圈，并通过实际射击验证效果，不用文字描述替代。

v0.1 必须能演示燃烧／爆炸、电弧／连锁两个构筑方向，不要求穷举全部组合。

触发规则区分原始攻击、子弹、持续伤害、爆炸与电弧。效果携带来源和触发资格；持续伤害、爆炸、电弧默认不能生成新的武器命中触发。设置可配置的触发预算与对象上限，不能仅靠“玩家应该不会遇到”规避循环。

## 7. 地图、敌人和营地

### 地图

生态区为“裂灯矿井”：矿轨、升降机、提灯装置、发光矿石、菌群侵占的机械设施。

采用手工模板拼接有限的连通地图，不做无限随机世界。10 个模板：入口 1、普通战斗 3、奖励 1、事件 1、安全点 1、秘密 1、精英 1、Boss 1。允许复用美术与模板；模板数不等于每局房间数。

第 1、2 深度段各有至少 2 个战斗房、1 个可选支路和结尾安全点。第 3 段包含精英与 Boss。主路线必须可达，不依赖秘密墙、随机钥匙或未解锁设施。

每局最多 1 个秘密房，以可观察线索提示。4 类事件：一次性急救站、废金换遗物的研究台、永久记录的旧档案、打开后出现守卫的封存矿箱。不做护送 AI 或复杂对话分支。

地图、掉落和遗物候选使用可复现种子；测试入口支持指定种子，同一内容版本内结果可重现。

### 敌人

6 种普通敌人分别承担近身追击、正面防御、远程投射、慢速重击、预警自爆、固定炮台。复用移动、生命和攻击组件，用节奏与轮廓区分，不堆复杂 AI。

精英复用一种普通敌人资产，增加一个清楚可读的强化动作。

Boss“矿坑吞噬者”是一只巨型矿井蠕虫。第一阶段用地面冲刺与岩块喷射，半血后加入有预警的钻地突袭。禁止不可躲避的全屏伤害；不实现动态挖洞、地图破坏或电影式镜头。

### 营地

营地是紧凑的工作台式准备界面，不是自由建造城镇。展示仓库废金、永久发现、当前解锁和出发入口。

只实现两项永久解锁：勘测台，暂定 50 废金，出发前显示首段一个支路类型；遗物匣，暂定 100 废金，可从已发现的辅助遗物中携带 1 件出发，候选仅急救封蜡、护灯铜环、探路透镜，携带物占 4 槽之一。

永久解锁提供选择而非无限数值成长。未满足条件时说明缺少废金还是尚未发现对应遗物。

## 8. UI 方向与设计规范

UI 必须适合实时动作游戏，不是网页仪表盘。世界画面是主角，面板只提供必要信息。

视觉语言：旧工业仪表、铜边金属、提灯光晕、冷色矿物。采用直角或轻微切角、薄描边、少量磨损；避免大圆角卡片、毛玻璃、大面积霓虹和装饰性假按钮。

| Token | 初始值／要求 |
|---|---|
| 背景 | #0D131A |
| 基础面板 | #17232C |
| 抬升面板 | #20333D |
| 主要文字 | #F1EADC |
| 次要文字 | #B2BBC4，不承担关键信息 |
| 行动强调 | #E6AA4A，提灯琥珀 |
| 信息与遗物能量 | #67C7D5 |
| 危险 | #E46B69，同时有文字或图形提示 |
| 安全／回收成功 | #80B69A，不能只凭颜色区分 |
| 间距 | 8、16、24、32 |
| 字体 | 清晰、授权允许使用、支持中英文；不采用难读的小号像素中文 |
| 字号 | 1280×720 UI 逻辑画布中正文约 18、说明不小于 16、标题约 28—36；支持缩放 |
| 控件 | 明确焦点与选中状态，交互区域目标至少 44×44 逻辑像素 |

世界可采用 640×360 低分辨率渲染并整数倍放大；UI 独立按较高分辨率绘制，文字清晰。现有工程若有合理方案优先沿用并记录。检查 1280×720、1920×1080、2560×1440；其他宽高比可留边，但不裁切交互区。

色板是初始方向，不代表全部组合天然可读。必须在实机截图中检查正文、焦点、危险预警与背景的辨识度。

## 9. 界面清单与交互

| 界面 | 内容与布局 | 状态和行为 |
|---|---|---|
| 主菜单 | 矿井升降机背景、标题、继续、新游戏、设置、退出 | 无存档时禁用继续并说明；覆盖档案需确认；没有假商店、账号或多人入口 |
| 营地／准备 | 中央工作台、左侧档案与仓库、右侧两项解锁、底部出发 | 未解锁、可购买、已拥有、余额不足、无辅助遗物均有真实状态 |
| 局内 HUD | 左上生命与等级、顶部深度、右上小地图、左下废金与死亡保留数、底部技能及遗物槽 | 实时更新；冷却可读；交互提示只在有效距离出现；关菜单不误触攻击 |
| 遗物三选一 | 三张等宽卡：图标、名称、效果、条件、构筑关系 | 暂停战斗；候选不重抽；可跳过；满槽有可取消的替换预览 |
| 遗物／角色详情 | 当前 4 槽、基础数值、效果来源、构筑标签 | 不做无意义空装备格；键鼠及手柄可读详情；空状态有解释 |
| 地图 | 已探索房间、当前位置、已发现安全点与入口、未知区域迷雾 | 不泄露未发现信息；图例不只用颜色；按键可关闭 |
| 撤离抉择 | 左侧现在可带回数量，右侧下一段危险与奖励规则，底部两个选择 | 数字来自真实状态；下一段信息来自生成配置；不用虚构概率 |
| 结算 | 标题区分撤离、死亡、完成远征；回收明细；回营地 | 显示获得、损失及永久发现；只发一次奖励；连点不重复到账 |
| 暂停／设置 | 继续、操作、音量、画面、语言、辅助选项、退出 | 暂停世界；退出说明保存策略；返回原焦点；设置保存生效 |

风险低／中／高仅对应三个深度段，不另做压力计。M1 未实现等级、小地图、脉冲时不显示为可用功能。

工具提示说明实际效果与条件，不只写“提升力量”。物品有图标、名称和标签，不仅靠颜色识别。

弹窗统一使用可管理的栈：最上层接收输入，Esc 返回上一层；最后一个暂停面板关闭才恢复战斗，不能关掉详情后背包仍开着而敌人恢复攻击。

按钮包含正常、悬停、焦点、按下、禁用状态。未实现功能不显示为可用按钮；加载状态只在真正加载时出现。

## 10. 输入、本地化与可访问性

键鼠：WASD 移动、鼠标瞄准、左键普攻、右键脉冲、空格冲刺、E 交互、Tab 遗物详情、M 地图、Esc 暂停／返回。

基础手柄：左摇杆移动、右摇杆瞄准、RT 普攻、LT 脉冲、A 冲刺、X 交互、Y 详情、Back 地图、Start 暂停；菜单方向键／摇杆移动焦点、A 确认、B 返回。界面打开时这些键不能同时驱动角色。

使用输入动作映射，提示跟随设备变化，不把键位写死在图片里。M1 先做键鼠；手柄是后续验收，不提前宣称完整支持。

简体中文与英文在菜单、物品、提示、结算实际切换。给英文留约 40% 扩展空间，靠布局适配而非不断缩小字号。

设置包含主音量、音乐、音效、全屏／窗口、UI 缩放、语言、震动、闪烁强度、伤害数字开关。默认不联网、不收集个人信息。

## 11. 技术实施

先检查仓库，已有合理技术栈不擅自重写。没有工程时默认 Godot 4.x 稳定版、GDScript、2D 场景与兼容性导向的渲染方案。核对实际安装版本、对应官方文档和导出能力，锁定确切版本，不凭记忆宣称最新。

不要偷换为 React 页面或 HTML 静态演示。不能运行 Godot 时可准备工程和代码，但将运行、测试、导出标为未验证，不能用概念图冒充实机。

最小架构：角色、敌人、投射物、房间、HUD 为独立场景；复用生命与受伤逻辑；局内状态与永久档案分离；遗物和敌人数值通过资源／配置管理；UI 订阅状态，不承担伤害和奖励结算。

不建立联网框架、通用 ECS、复杂依赖注入、全能事件总线或大型关卡编辑器，只抽象当前真正需要的内容。

| 模块 | 责任 |
|---|---|
| RunController | 远征状态、房间流转、胜负与结算 |
| Combat／Health／Projectile | 伤害、攻击、投射物、来源标签 |
| RelicSystem | 装备槽、效果、候选、防循环 |
| DungeonGenerator | 模板拼接、连通性、种子、房间信息 |
| ProfileStore | 永久档案、设置、快照、版本迁移 |
| UIController | 页面、弹窗栈、焦点、输入模式、本地化 |

后续远征恢复采用房间入口快照，不保存每颗飞行子弹。退出或崩溃后恢复最近房间入口，告知当前房间未提交进度会回退。快照包含生命、经验、废金、遗物、地图、随机状态与已生成候选等必要数据。

不能一边将房间收益永久入账，一边恢复时再生成。死亡、撤离和完成提交后使旧快照失效。

存档含 schema_version，使用临时文件、原子替换和备份；读取失败保留损坏文件并提示，不静默删除数据。

素材只用原创、已授权或明确允许使用的内容，记录来源与许可，不提取竞品素材。缺正式资源时使用统一原创占位图形和简单音效，标注替换点。

## 13. 验收与测试

### M1 必须验收

从主菜单新游戏进入可操作场景；击败敌人、拾取废金；三件遗物有实际差异；可主动撤离、可生命耗尽死亡。

两种结局计算正确且只结算一次；回营地可再出发；重启后永久废金和档案正确；暂停停止敌人及投射物，恢复无输入穿透。

至少有一个固定测试场景，能够确定性选择并验证三件遗物，不依赖随机碰运气。

### v0.1 完整验收

至少 3 个固定种子均能到达安全点及 Boss，无不可通行生成；燃烧、电弧方向各有可复现路径；4 遗物共存不无限触发。

分别测试提前撤离、死亡、Boss 胜利；覆盖满槽替换、跳过奖励、升级受伤同帧、结算连点、满血治疗、房间恢复、损坏存档、语言切换、手柄焦点、分辨率。

性能目标为记录下来的测试机器上稳定接近 60 FPS，采用约 30 敌人、60 投射物的压力场景采样。只有测量后才能报告结果，不声称“低配无压力”；说明测试密度的边界。

规则测试至少覆盖死亡保留及向下取整、重复结算、触发循环、重复命中、存档读写、种子一致性和候选不重抽。不能自动化的项目提供人工步骤。

试玩只记录事实：首次操作是否顺畅、能否解释损失、能否感受遗物差异、结束是否主动再出发。不捏造人数、反馈、留存、愿望单。
