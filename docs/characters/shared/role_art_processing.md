# 三职业手绘动作源与本地整理记录

更新：2026-10-03。当前正式交付为三职业八方向共享身体家族（schema 3），已启用并经真实 Main 图形检查。旧 schema 2 `combat_clips.json` 仍关闭，不代表十二技能各自的连续八帧动画已完成；旧来源与兼容路径保留。CH03 实际战斗已为成年暗黑女性法师，旧男性工程师不再被已准入的新家族选中。

## 正式八方向规格

用户最终确定角色采用八方向：`E、SE、S、SW、W、NW、N、NE`，以屏幕坐标顺时针每 45° 取样。移动、瞄准和真实技能方向仍是连续向量，只有身体精灵选择离散方向。十二方向不是生产要求；此前 30°／60° 候选不能改名冒充 45°。合格的东、南、西、北源可复用，四个真实斜向另行制作。

当前已准入 schema 3 共享动作家族：每方向八个独立姿态（待机、左步、右步、普攻准备、释放、收势、闪避、防护／施法；枪手最后一姿态用于装填），每人 64 姿态、16 张 A/B 源，三人合计 192 姿态、48 张源。它供十二技能按明确类别选用身体动作，并不等于每技能都有独立八帧连续动画；schema 2 的完整逐技能标准保持不变。

[共享家族整理工具](../../../tools/art/build_shared_action_family.py) 复用现有连通主体分离，逐个像素唯一归属，按同方向统一站立参考与脚点 1:1 打包；不镜像、不旋转身体、不按蹲身高度逐帧放大。八方向全部有效后才允许原子启用，不能混用新旧身份。方向切换保持动作相位，脚点、身体尺度、左右持武器及释放锚点须在实际游戏中复查。

八方向与十二方向的资料结论依据 [Flare 的八方向定义](https://github.com/flareteam/flare-engine/wiki/Attribute-Reference)、[FreedroidRPG 的八视角动作制作](https://www.freedroid.org/dev-section/graphics/rendering-graphics/) 和 [Godot 保持动画进度的方法](https://docs.godotengine.org/en/stable/classes/class_animatedsprite2d.html#class-animatedsprite2d-method-set-frame-and-progress)。它们支持八方向作为完整可用规格，不代表行业统一规定方向数。

## 来源与工具范围

三人立绘及手绘动作由内置 ImageGen 按用户指定的原创身份生成，提示、参考和实际尺寸保存在各 PNG 旁的 `provenance.json`、`source.json` 或 `generation.json`。请求尺寸是 2048×2048；当前动作源实际为 1254×1254，未上采样，不能称为原生 2K。

[美术来源总记录](../../../assets/characters/role_art_sources.json) 中生产 SVG 只指三个职业徽记和七状态小星灵。三十六技能图标已由内置 ImageGen 逐项原创重绘为透明 PNG，各文件及完整提示位于 `assets/characters/<role>/skills/skNN_icon.png` 和同名 `generation.json`。全部实际原生尺寸为 1254×1254，哈希与原输出一致；未放大，不能称为原生 2048。2K 界面实际图标为技能池 84、装备槽 96、详情 132、HUD 112 像素，原生图标细节足够覆盖这些位置；44 像素总览已检查不同技能轮廓。世界角色另受镜头缩放影响：当前 112 世界像素身体、常规 0.85 镜头、2560×1440 相对 1280×720 的 2 倍画布下，约为 190.4 屏幕像素；审核 contact 的 224 像素是统一比较尺寸，并非普通镜头实战身体高度。特效使用已有世界坐标缩放，不额外再乘二。

[图标与星灵工具](../../../tools/art/build_role_combat_art.py) 登记已交付手绘技能 PNG，生成徽记和小星灵，不重新把技能路由指回旧 SVG；缺少 PNG 时直接拒绝。旧技能 SVG 不再登记到三十六技能身份，仅保留未消费的地雷／哨机兼容别名。工具不覆盖已有生产动作目录。平面 SVG 人物动作及其旧工作副本已经退役，留在忽略目录 `tools/godot/art_preview`，不注册为正式人物动作。

用户已授权本地逐帧分离、透明边缘整理、脚点对齐和图集打包。[本地样板处理工具](../../../tools/maintenance/prepare_role_action_samples.py) 使用现有捆绑 Pillow／numpy，无新增依赖，保存原始源 PNG：

- 不带参数时处理三职业；`--role warrior`、`--role gunner` 或 `--role mage` 只处理指定职业。唯一入口整理当前 A/B 两张 2×2 四帧源，每张必须存在四个独立 alpha 主体，主体贴接时直接拒绝，避免猜测完整武器。
- 旧 `--split` 参数仅作为兼容别名，仍走同一 A/B 处理入口；退休的 4×2 八帧源和六十四小帧源不再由此工具处理。
- 清除 alpha 小于 8 的极弱透明杂点，并将全透明像素的隐藏 RGB 归零；其余保留 1:1 原生像素，不补画、不锐化、不拉伸。
- 以独立主体连通分量分帧，少量分离装饰像素归到最近主体边界。保存 alpha≥8 的像素唯一归属检查。
- 手工靴底标记只作为审核锚点，遮挡或目测误差在 JSON 中标明；正式使用前需复核。每个职业的八帧共用一个图集脚点。
- 每帧头发到可见靴底的高度单独记录。运行比例只应使用统一站立参考尺度，不能依据弯身、抬脚或帽／斧包围盒逐帧放大。

正式 schema 2 方向组要求 `reference_body_height`，八帧共用一次站立参考比例；各帧的 `body_height` 只用于核对真实像素密度。正式家族必须同时覆盖八方向、普攻、站立、行走、闪避和十二技能，枪手还必须包含装填。源脚点和所有释放锚点必须位于各自合法区域内。

## 新 A/B 四帧源

后续生成采用 A 帧 0–3、B 帧 4–7 的两张 2×2 源，合并为三准备／两释放／三恢复。每个格包含完整人物和武器，要求实际透明边距，固定高机位东南视角、身份、衣装及尺度。检查实际 alpha 连通主体和外边缘后再处理，不能按名义四等分裁剪。

每套整理为两张 1536×1536 透明审核图集，单格 768×768，保留源像素 1:1。派生图集 `basic_southeast_aligned_a/b.png` 只保留在忽略目录 `tools/godot/art_preview/<role>/split_native`，数据 `basic_southeast_split_review.json` 保留在职业动作目录供审查；纹理未注册到生产资源总索引，`enabled` 与 `production_ready` 均为 `false`。

新战士实测可见人体高度为 464／432／436／466／496／474／567／555px。A 来源取初始 ready 464px，B 来源取末尾 ready 555px，各来源内部固定一个参考尺度。第零／第五索引帧有一靴遮挡，目测标记误差约 ±12px，遮挡位置可达 ±35px。原生起末可见高度比 1.196，连续性预览将 B 来源所有帧统一下采样到 0.836036，A 保持 1.0，统一脚点；没有逐帧补偿弯身高度，也没有修改原图或原生图集。审核 contact 中头身尺寸更接近，但斧刃／柄与局部衣装仍有来源差异，正式连续动作未验收。

三套新 A/B 各有四个独立主体，alpha≥8 和 alpha≥128 的画布外边接触像素均为零，人物与主武器完整。分帧过程对 alpha≥8 像素逐个唯一归属自检通过，透明图集边界均保留空间。

枪手两只靴底均可见，标记误差约 ±4px，整理后未见旧枪口裁切或相邻帧污染。法师的后靴在第二／第三／第六／第七索引帧部分遮挡，标记误差约 ±14–18px；其 B 来源的站立参考约 407px，低于 448px 细节门槛。帽尖和法杖使整个人物的不透明包围框达到约 540px，不能拿这个数字替代真实人体高度。

如果继续提高法师源细节，应采用每张两帧、2×1 高格的生成布局，给大帽、法杖和人体足够的纵向空间；仍要求人物和完整武器相互分离及外缘透明。已有四帧生成记录保留真实尺寸，本地处理没有补画缺口或通过放大掩盖指标。

最小可复现审查交付为每职业两张最新 `basic_southeast_a/b.png`、各自两份 `generation.json`、一份 `basic_southeast_split_review.json`，以及处理工具和本记录。原生派生图集、比例预览、GIF、旧候选和重复截图只留工作副本，不加入发布资源或批量暂存。

当前审核结论只确认本地处理可复现、像素保留和图集边界有界。正式验收仍需全方向连续动作、实际手／枪口／法杖锚点、三十六技能时序、目标 2K 屏幕可读性以及新版 UI 内的自然战斗检查。
