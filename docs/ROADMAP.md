## M0—M1 最小实施顺序

1. 保留正式项目 `D:\dev\zgame\abyss-delver` 中已有 Phaser 工程，在其 `godot/` 子目录交付原生 Godot 工程；记录实际引擎和图形环境。
2. 集中配置战斗与损失参数，分离永久档案与局内状态，先保证一次性结算和存档故障处理。
3. 实现固定房、玩家、敌人和主弹，跑通死亡与主动撤离。
4. 加入三件固定可拾取遗物、废金、来源标签及触发上限，验证真实攻击差异。
5. 接入菜单、营地、HUD、结算、暂停／确认栈、本地化和实际可用设置。
6. 运行规则检查、真实引擎流程及视觉检查；记录已验证和未验证项目，给出可复现运行方式。

## M1 后的优先级

截至 2026-09-28，已有 core 68、combat 32、headless UI 26、图形 UI 36、UI 边界 62、跨进程 45、渲染战斗 18 个通过断言。计数不是玩家人数或性能数据；真人手感、完整分辨率组合、硬断电与长期性能仍未验证。Windows 导出在最终迁移后执行。

| 优先级 | 下一项 | 前置条件与完成证据 |
|---|---|---|
| P0 | 修复 M1 结算、保存、输入或流程阻断缺陷 | M1 两结局、重复结算、重启、暂停回归通过 |
| P1 | 真实键鼠试玩与战斗节奏调整 | 记录首次操作、遗物辨识、损失规则理解；不捏造试玩人数或反馈 |
| P1 | M2 的最小房间连接与撤离／深入抉择 | 固定种子主路线可达；不先扩展无限随机地图 |
| P1 | 经验升级与遗物选择事务 | 候选保存、关闭不重抽、跳过不重复领奖、满槽替换可取消 |
| P2 | 两个构筑方向和敌人节奏逐步扩充 | 每加一项确认伤害来源与触发预算；燃烧／爆炸和电弧／连锁可复现 |
| P2 | 后续地图、事件、精英、Boss | 基础战斗和结算稳定，地图有可复现种子 |
| P2 | M3 的房间入口快照与营地解锁 | 快照不能与已入账收益重复；升级存档 schema 并验证迁移 |
| P2 | 手柄、完整设置、音效与美术统一 | 输入设备切换、焦点、目标分辨率均有实测记录 |
| P3 | 性能与正式 Windows 发布验收 | 记录机器与 30 敌人／60 弹体场景数据；实际导出和干净启动 |
