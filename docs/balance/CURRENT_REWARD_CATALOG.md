# 前四副本奖励现状附录（重构确认稿）

记录日期：2026-10-01。**本册仅记录当前运行的 `reward_policy_version=1`，没有修改金币、经验、历练或装备掉落。** 新成长、独立实例、随机属性、品质及锻造规则由重构主文档定义，本册是实施前的基准。

当前前四副本共24个战斗房模板、4个独立首领、2个可选宝箱。远征会按路线选取或复用模板，表中“每房”是一次成功清场结算，不能把24模板相加当成每次远征固定收益。自然怪击杀金币和重复装备折算金币在清场奖励之外计算。

当前入口由 [ExpeditionState.fresh](../../scripts/core/expedition_state.gd#L67) 保存 `reward_policy_version=1` 和所选难度；实际奖励由 [RoomRewards.build](../../scripts/world/room_rewards.gd#L14)、[RoomRewards.optional](../../scripts/world/room_rewards.gd#L33) 生成，由控制器按一次事务提交。本册所有金币均来自 `policy 1` 的 `full` 路径，不抄旧 `policy 0` 的减载、维修、移动、主题二选一或基础两件分支。

## 1. 当前统一计算规则

难度 `D=0/1/2/3/4` 对应普通、进阶、困难、险境、极限。合法 `policy 1` 必须显式传入D；`difficulty=-1` 只属于历史兼容路径。

| 项目 | 当前计算方式 |
| --- | --- |
| 清场基础金币 `G0` | 普通房取历史 `_options` 中 `full.gold`；四首领统一80；可选箱L01为18、L11为22。 |
| 难度金币 | `G=round(G0×(1+0.25D))`；为正数时0.5向上取整，例如18×1.25=22.5→23。不是对每个小项先取整再相乘。 |
| 普通房装备抽取数 | `min(1+(D≥2?1:0),本族职业适配池大小)`；即1/1/2/2/2。所有24房统一基础1件，即使旧 `_options.full.count=0/2` 也不沿用。 |
| 首领装备抽取数 | `min(2+floor(D/2),本族职业适配池大小)`；即2/2/3/3/4。 |
| 可选箱装备抽取数 | `min(1+(D≥2?1:0),本族职业适配池大小)`；即1/1/2/2/2，箱子不再次发房间经验与历练。 |
| 普通房经验 | 每次成功清场30，五难度相同；实际增加量受当前英雄经验3600上限限制。 |
| 首领经验 | 每次成功击败并清场80，五难度相同；实际增加量受经验上限限制。 |
| 普通房历练 | 每次成功清场180，难度不放大；远征历练最多900。 |
| 首领/可选箱历练 | 0，不套普通房180的默认回退。 |
| 装备生成强化 | 下限 `a=max(0,D−1)`；上限 `b=a+(D==1?1:0)`；首领且D≥1时a、b各+1；最后各限制≤3。仅D1在[a,b]整数均匀随机，其余档固定a。 |

| 普通房/可选箱装备抽取数 | 1 | 1 | 2 | 2 | 2 |

所有本族普通房D0已有至少28只自然怪，因此完整清场通常可以生成36金币；是否全部收集仍取决于拾取和房间离开前的处理。召唤物即使参与了清場条件，也不单独增加该额度或发经验。

## 6. 历练、经验和装备重复的结算边界

### 6.1 历练是本次远征的遗物成长

历练阈值为 `[0,100,240,420,640,900]`，最大900、阶位最大6。入口提供初始阶位的遗物选择；之后每次普通房清场增加180，首领与箱子不增加。

| 已成功清场普通房数 | 累计历练 | 当前阶位 |
| --- | --- | --- |
| 0 | 0 | 1 |
| 1 | 180 | 2 |
| 2 | 360 | 3 |
| 3 | 540 | 4 |
| 4 | 720 | 5 |
| ≥5 | 900（封顶） | 6（封顶） |

来源：[MASTERY_THRESHOLDS](../../scripts/core/expedition_state.gd#L17) 与 [完成结算/遗物邀约](../../scripts/core/run_controller.gd#L1076)。这900历练不存入英雄等级经验，也不延续到下次新远征。

### 6.2 英雄经验与死亡

清场事务把30/80经验加入永久英雄经验，当前上限3600，对应最高20级；已经结算的经验和等级在后续死亡时保留。旧房间的XP回调在远征里只暂存事件ID，完成payload的xp是权威总额，不能再叠加一次相同房间30。首次引导完成另有一次30经验，不在每房基础表中。来源：[grant_hero_xp](../../scripts/core/run_controller.gd#L644)、[completion XP](../../scripts/core/run_controller.gd#L1047)。

当前 `dynamic_version=2` 单种族远征死亡不发“未清场击杀安慰经验”；历史v1才可能按 `min(未清场奖励击杀数×2,18,3600−已有经验)` 发放。不能把这条历史函数当成每只野怪常规2经验。来源：[FieldLearning.calculate](../../scripts/core/field_learning.gd#L9)。

### 6.3 装备数量是抽取数，独立保留件数可能更少

当前 [_race_reward](../../scripts/world/room_rewards.gd#L161) 每次发奖先选未发现的本族职业适配模板，耗尽才选重复模板，同一次奖励内不重复选模板。`owned` 当前传入历史发现记录，因此卖掉装备不会重置首次发现优先级；`pending` 本局待入库模板也参与排除。种族掉落不会回退其他族。

| 新掉落与已拥有/待入库的关系 | 当前处理 |
| --- | --- |
| 新模板或高于永久旧强化 | 暂存 `pending_equipment[template_id]`，成功撤离后才永久保留。 |
| 高于本局同模板待入库强化 | 新掉落替代待入库最高强化，较早记录标为superseded，不改玩家正在穿的旧版本。 |
| 本局已有不低于它的待入库版本 | 新重复掉落折算金币。 |
| 永久已有不低于它的强化 | 新重复掉落折算金币。 |
| 重复金币 | `int(模板当前price/10)`，正整数截断；记录对应economy_version，历史收据按历史定价验证。 |

来源：[_add_equipment_drop](../../scripts/core/run_controller.gd#L892)、[重复价格收据验证](../../scripts/core/expedition_state.gd#L210)、[成功撤离的强化保留](../../scripts/core/run_controller.gd#L311)。因此“房间给2装备”指2次抽取，不保证永久新增2个模板；现状不会生成可同时保留的不同随机属性同模板实例。

## 7. 新奖励方案需要处理的兼容成本

以下只是实施边界，**不改变第1～6节的现状数值**。新主方案拟采用 `ceil(G0×2×(1+0.25D))`，普通房/首领经验采用 `ceil(30或80×(1+0.25D))`，历练保留当前规则，装备数量转到新主方案表。

| 改动 | 必须处理的兼容点 |
| --- | --- |
| 金币从round改ceil且加基础×2 | `G0` 应取本册基础值，不能取已按D缩放的当前金币再缩放一次；例如当前18/D1=23，新计算应从18出发，不能23×2×1.25。清场预览、发奖与日志共用新政策。 |
| 新奖励版本 | 当前验证器只支持reward_policy_version≤1；新增版本和路由。已有进行中远征继续按冻结版本；不能把新政策直接覆盖policy1或删掉policy0。 |
| 可选箱政策 | 当前 `optional_claims.reward_version` 只接收1/2，并按旧round金币、旧数量严格核对。新金币/抽数需要新箱收据版本及对应验证，旧已领取箱不能因改政策重开奖。 |
| 经验按难度提高 | 清场payload必须唯一权威，不和暂存30回调重复结算；存档校验与等级上限/阈值同步升级，保留既有已结算经验。首次引导30仍为独立一次事件。 |
| 装备抽数、品质与实例 | 当前待入库用模板ID键去重，抽数上限8、总drop ID512、强化上限5；随机实例要按实例ID保存，取消自动以模板重复折算，仍保留历史重复收据的验证。 |
| 金装最高+2规则 | 不能把旧野外+3强化降级；新实例按品质与来源限制生成强化，玩家已有强化与锻造强化另行保存，不与掉落生成强化混写。 |
