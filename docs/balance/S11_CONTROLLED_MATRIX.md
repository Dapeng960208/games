## 固定样本

`tests/support/s11_battle_fixtures.gd` 冻结84份合法实例配置：B01–B04 × CH01/CH02/CH03 × G2/P5/G0/mixed/green/white/lowG2。每个章节三职业为12组；不把尚未发布的B05–B12算作已制作或已验收。

- 角色等级与八件装备ilvl均为5B；天赋为4主力、5主力4精准、5主力5精准4敏捷、5主力5精准5敏捷4灵巧
- B01战士/法师S01，枪手S02；B02战士S04，枪手/法师S03；B03战士S06，枪手/法师S05；B04战士S07八件，枪手/法师S07六件＋S03武器/戒指
- B01–B03无分支；B04固定Q/B、R/A。技能的强化、成本、范围与解锁均读实际等级的生产规格
- G2金+2、P5紫+5、G0金+0、mixed六金+2＋紫+5武器/戒指、green绿+3、white白+5；以上k/u50且每阶g10。lowG2为k/u25、金+2、每阶g8
- 词条按章节标尺的固定优先顺序，先过滤槽位/类型，再取4/3/2/0条；模板ID、每条过滤结果、真实主属性/词条金额与封顶损失全部写入manifest
- 实例按已获得的合法预强化装备建立；规范价格峰值来自生产InstanceEconomy，实际支付账本为空，不把规范价格伪造成已付金币
- 每组种子固定1001–1010，G2/P5/各对照共享种子和控制规则。固定构筑不消耗随机数

Boss私有AI与全局暴击都必须使用指定战斗种子。生产房间原先以0调用Boss配置，受控夹具现在在开钟和任何原生物理帧之前，通过生产`configure_boss(id,D,seed,2,frozen_snapshot)`配置实际seed；初始满HP、正常护盾和完整机制不变，不在战斗中改随机状态。报告记录实际`boss_seed`和私有RNG seed。先前v4–v7诊断的AI仅使用默认seed，不能当作完整十种子验收。

D4七样本共840场；另跑同G2的D0–D3共480场，加上已存在的D4形成1320场主体矩阵。普通/精英、阶段定向和单包容错样本单列，不能把1320场自动等同全部S11完成。

## 实际执行与控制器

`test_s11_battle_matrix.tscn` 经生产 `Game.start_run` 验证并落入隔离档案，生产Boss房从人工入口初始化。房间几何、导航、碰撞、机关、首领、召唤、技能、接招队列、资源、冷却、受击、状态、装备与套装均使用生产节点。任何战斗内HP、伤害、状态、位置、阶段和冷却都不由驱动器写入。

控制器 `s11_battle_controller.gd` 当前候选版本 `s11-controller-v8` 每0.1秒进行战术决策；持续普攻按60Hz原生物理帧检查实际冷却，鼠标瞄准通过真实viewport输入每物理帧跟随当前可见目标。没有直接改写玩家aim变量；需要等待原生输入更新后才提交方向技能。v4基线报告单列；v8尚需统一重跑才能纳入校准。顺序为：

1. 根据当前可见预警、锁定区域、地面区域与弹体位置，选择可通行的安全目的地；当前锁定威胁命中脚点时请求合法闪避
2. 优先反制机关：太阳盾存在时接通能源；有限卵囊、战鼓用实际普攻击破；墓穴到场交互。不领取补给、药物、信标或外部遗物
3. 攻击首领；近战目标距离72，枪手/法师通常230。法师根据最高优先级已就绪且可支付技能的实际范围趋近：E最多115，W最多200；终点容差8，确保进入真实施法距离。仍检查真实射程与视线。首领死亡后仅在其它观测流程中由调用者决定后续目标
4. 无正在执行的技能/闪避/接招时，合法技能按E→R→W→Q优先；目标不在技能真实范围时暂缓，无足够资源则尝试其它合法动作；持续请求普攻
5. 完整技能释放期间不发新的攻击打断它；躲危险可以正常取消技能，报告仅统计真实已到达目标的包，绝不补记理论整段伤害

候选v6的法师W用统一地面摆放策略：围绕当前敌人采样70/90/110距离、16方向，必须在220施法范围及160法晶攻击范围内、避开敌人体积、真实可走地面、视线畅通且当前可见预警无危险；以当前可见速度×1.55秒（法晶首射等待）作线性位置预估，优先覆盖该点。只用当前速度，不读取未来AI。W每次新建法晶、最多两个；E才引爆260距离内相连节点，Q和R沿实际机制充能。v5的140边缘摆放让节点活得更久却可能在首射前失去射程，未作为已改善循环的证据。

候选v7补全E的真实遥控范围：本体新星能命中，或玩家260距离/视线内的活跃节点以`100+20×充能`爆炸半径覆盖目标，都允许合法E；两段视线分别检查。已有合法遥控爆炸时保持原位施放，不强迫法师先走入本体新星范围。此规则不更改任何成本、系数、冷却或节点状态。

候选v8处理无效站位：首选保持射程的落点被地形/导航拒绝时，围绕目标检查可走、可见且没有当前预警危险的接近点，逐个提交真实路径请求；必要时用生产导航缓存得到附近合法途经点，再通过普通移动请求走到那里。保留拒绝/回退日志，禁止改地形或直接重写角色位置。

所有动作经 `request_move/request_attack/request_skill/start_dash/room.interact` 的生产入口。安全方向采用16方向×90/150/230距离的确定性采样；这是明确披露的受控策略，不能声称等同人类反应。它不会读取未来随机选择，不为特定品质或Boss更换策略，不调整敌人命中率来追目标。

头显无关的headless运行使用 `--fixed-fps 60`、原生60Hz物理、`Engine.time_scale=1`。该引擎版本的headless后台无法编译环境绘画的custom sampler，因此只有不拥有玩法状态的MineBackdrop换为测试专用空绘画接收器。游戏几何和所有战斗节点保留；该运行不提供像素、声音或手动游玩的证据。GPU/手动场景保留正常背景。

headless复用控制器时必须将房间放入1280×720、`handle_input_locally=true`的SubViewport。Root Window可能重新采集不存在的物理鼠标而覆盖虚拟事件，造成方向技能偏离；控制器对此错误入口断言失败，避免把未生效输入记录成成长/平衡结果。

## 记录与计时

从解除初始准备暂停至首领完成信号计时，包含从入口接近、全部免疫/预警/机关/跑位/治疗。`simulation_seconds` 是原生引擎战斗时间，`host_wall_seconds` 是未限帧执行在主机实际消耗的时间；加速执行不能把后者宣传成游戏TTK。准备载入耗时另记，战斗中的暂停另记。默认180秒仍未结束即记time_limit，保留失败/删失结果，不能选择性删除。

记录每场胜负、实际HP/盾/资源、实际收到的每个原包/防御后金额/HP损失/盾吸收、输出目标与来源、弱点窗口输出、三阶段驻留/释放、装备ICD启动、机关反制、职业层数、技能接受/拒绝、资源为零时长。纯观察覆盖生产伤害记录及表现回调，再调用原实现；不改变结算。

实际有效治疗以耐久守恒另算：玩家结束HP－初始HP＋实际累计HP损失；首领结束HP－初始HP＋实际累计HP损失。盾吸收独立累计，不能在已扣盾的HP损失上再减盾一次。对未知归因单列unknown，不能据此虚构有效DPS。

阶段无施法不强行等待：记录 `phase_casts_skipped_by_output_or_termination`。阶段定向检查必须另列初始化条件和完整预警/反制/实伤证据，不混入自然阶段流转的TTK中位数。若被击败/超时且尚未进入阶段，必须按终止区分，不能把它称作输出跳过。

阶段补充工具 `test_s11_directed_observation.tscn` 使用独立 `--experiment phase_coverage` / `p3_tolerance`，其报告必须包含 `baseline_ttk_evidence=false`，汇总不进入普通Boss胜率/TTK门槛。前者在当前阶段暂缓进攻，维持合法移动、闪避和机关反制，最多观察75秒再恢复正常攻击；缺失招式仍如实记录，不能把被机关抑制的招式冒称释放。此75秒只属于定向覆盖，不是自然战斗时间。

若永久机关反制使后续阶段无法释放原招，独立 `--starting-phase 1/2/3` 将每一阶段作为单独初始夹具：P2/P3仍在开钟前通过CombatHealth按真实阈值设置初始HP，原生首帧执行阶段进入；阶段观察中暂不攻击或反制，使用真实移动/闪避，直到该阶段完整动作池都实际释放、玩家死亡或明确观察上限。三种结局分别记录；这一条件只服务招式覆盖，正常基线中的反制和时长不改变。目标危险包即使致死也保留并记失败，不能被父类的死亡停止条件误记为未观察。

P3容错夹具在任何原生物理帧和时钟开始前，通过实际CombatHealth.damage接口把首领初始HP设为其原生P3阈值的向下取整值。自然选招诊断保留第一物理帧进入P2/P3的流程；独立单招夹具则在开钟前以0.000001准备delta调用原生BossBrain.tick完成阶段进入，保留原生P2/P3增援请求，并以明确支持场景夹具的`_begin_action(actor,player,forced_action)`启动指定危险招的完整原生预警。玩家初始位置选择在真实可走地面、视线畅通且招式范围内，坐标、原因、准备delta、增援队列、指定action、完整tell/lock和初始command均记录。它是人工单招初值，不代表无偏AI选招、自然阶段转换时长或从P1打出的成绩。

玩家仍以真实满HP、正常资源、无已有盾入场；装备静态减伤保留，无战斗中HP/盾/冷却/阶段/位置重置。开钟后仅使用真实导航等待预警并承受实际结算包。接收器内即时记录满HP、零盾、无临时减伤/无敌/闪避保护、P3及精确attack_id；已有意外伤害、同一时刻多包或DOT不合资格，不重置后再算合格。实际包必须存活且HP损失≤20%才通过。2026-10-01的B01/CH01/G2/1001单招基础设施样本通过：完整2.033秒预警/锁定后1356原包→662HP损失，占6217最大HP的10.65%；不能据一个案例推断全部十二组/候选系数已通过。

## 运行与报告

`tools/balance/run_s11_matrix.py --output /tmp/s11-run --suite full --workers 3` 执行主体矩阵；`--suite d4` 或 `--suite ladder` 分开执行，支持章节/职业/样本/种子筛选。输出目录必须在仓库外；每个进程拥有独立XDG、test_s11存档、日志与JSON。

普通/精英用 `--suite rooms`：L01–L24×D0–D4×三职业、默认G2/seed1001，共360个实际有限波次/目标场景。夹具使用合法真实远征容器停留在入口，受控房间的node_index不匹配奖励提交点，因此观察实际objective_complete但不把受控通关当作合法获得奖励/成长。每个演员保留初值、模板/rank、实际HP/盾轨迹和死亡退出时点；目标物件另列，不能混入普通/精英存活与伤害统计。

实际规划器只在D≥2、指定elite_objective房间的后续区域/波次配置精英，因此作者房间D0/D1不提供精英受击证据。独立 `--suite ladder --experiment elite_fixture --seeds 1001` 在生产服务场地创建一名真实精英：B01/M05滚轮猎犬、B02/M15掘地锹甲、B03/M22熔糖炮手、B04/M34反击卫；等级固定5B，真实resolve/spawn_enemy链路，同模板跨D0–D4，三职业共60场。这个人工单演员夹具保留实际AI/受击/资源，关闭其奖励，既不声称是作者精英波次，也不声称覆盖全部18种自然行为。过快击败而未释放技能仍记零次，不能补造原包。

最终计时复核使用 `--real-time --gpu --workers 1`：不传`--fixed-fps`，以真实时间运行并将渲染上限设为60FPS，显示完整实际场景。报告并列物理步数、渲染帧数、物理delta范围、游戏模拟时间和主机墙钟。至少复核12组G2/P5共24场，并补充最终边界/失败及需要的lowG2样本；未实跑不能记为已具备GPU/实时等价证据。加速矩阵没有资格证明人类取得装备或学习操作所需时间。

可加 `--screenshots` 保存真实图形视口的开战前/结束后PNG。两次捕获都在战斗计时间隔之外：开始图等待已准备场景绘制后才开钟，结束图在时长与结局封存后绘制，记录UTC、原生物理步数、实际尺寸、路径和捕获墙钟成本。不会为了截图暂停进行中的战斗，图片不当作手动操作证据。CLI的`--gpu`只表示启用图形窗口，不能据此声称硬件GPU加速；报告记录RenderingServer实际适配器/API及引擎日志的设备行，Mesa llvmpipe等软件渲染器如实标明。`--disable-render-loop` 是独立的加速headless候选开关，协议显式锁定；禁止与图形窗口、实时或截图结合，未完成同种子实际玩法散列对照前不采用到最终矩阵。

`tools/balance/freeze_s11_candidate.py` 在新建分离工作树中冻结当前源码和变更，使用唯一901–1000测试归档编号试调静态章节/rank参数；不改源工作树或公开版本1。默认独立复制导入缓存；只有来源本来就是不可变S11快照时才允许链接只读导入产物。正式采用的数值仍需新的公开版本和最终不可变快照验收，不能把测试901版本直接发布。

每场保留fixture/参数散列/实际技能规格；批次保留Git HEAD、工作树状态和相关源码SHA256。`--resume` 只有源码散列一致才复用已有完整报告；数值改动后必须新开输出目录。`--summarize-only` 从已有raw JSON汇总。引擎退出0同时要求日志无SCRIPT ERROR/ERROR；过程成功不代表数值门槛通过。

Schema v2将有序种子列表、模拟/实时模式、GPU/headless、probe、观察上限、控制器、全运行源码/场景/参数、引擎二进制SHA和冻结校准共同写入measurement_protocol；请求的完整case列表另存run_request。恢复必须精确一致，不能以相同场数代替相同种子。汇总拒绝不同协议及旧的未锁定记录，不把异常退出的部分结果纳入平衡统计。

汇总逐12组判定：G2十种子全胜、TTK中位35–50秒、HP中位≥60%；lowG2十种子全胜、TTK≤60秒、HP≥45%；P5至少九胜，TTK比G2≥1.15或HP低至少15个百分点。胜局TTK中位与全场HP中位分列；失败数、超时数、最差值不能被中位数遮盖。G0、混装、绿、白没有人为失败门槛。D0–D4另报每同种子的反向时长案例，不能以机制例外隐瞒原属性或实际伤害倍率倒置。

2026-10-01基础设施探针：BO01/D4/CH01/G2/1001，10原生模拟秒，主机战斗3.41秒，14检查通过且无引擎/脚本错误。实际5次普攻、E/Q/W各1次，首领真实释放3招；探针在10秒人为终止，**不计通关或校准证据**。主体矩阵35–60秒×1320场约13–22模拟小时；主机耗时须按当前机器与并发实测，不以该10秒探针承诺最终工期。

控制器预验证发现并修正两项输入问题：v1的法师W目标距离230超出220施法范围、停步容差可能停在E合法距离之外；v1/v2仅每0.1秒写aim，下一物理帧会被原生鼠标坐标覆盖，技能前摇再次读aim导致方向偏离。v3改用真实viewport鼠标事件并等待原生输入，保持同一技能优先序、机关和避险政策。B01法师G2/1001定向复核中，7次Q实际释放、7次命中Boss、Q实扣15,436HP，44.77模拟秒/90.76%结束HP；仅1种子，不能代替十种子门槛。v1/v2运行记录仅作为控制器诊断，不能混入最终强度矩阵或据此削弱/加强职业与Boss。

v3随后发现持续普攻仍被0.1秒战术决策量化：B01战士G2的真实0.41806秒间隔和P5的0.5秒间隔可能都延后到约0.5秒，掩盖第四词条攻速。v4将连续普攻维护移至每原生物理帧，保留战术10Hz、真实冷却和完整技能释放；因此v3数值记录也仅供诊断，不进入最终十种子对照。
